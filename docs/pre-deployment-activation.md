# QuotaPilot 部署前激活与数据保留说明

> **当前状态：离线 Quota Policy / Decision Control Plane。** 未配置且未由工作区 owner 主动启用供应商凭据前，系统不得发起 OpenCode Go 或 OpenAI Provider API 请求，也不得声称已执行真实额度执法或真实任务执行。

## 1. 后续激活前提

用户下月开通服务并明确授权后，才可通过项目 Secrets 配置下列服务器端变量：

| Secret | 用途 | 处理要求 |
| --- | --- | --- |
| `OPENCODE_GO_API_KEY` | OpenCode Go 的后续模型目录与额度同步、连接测试 | 仅由服务器读取；不得提交、返回至浏览器、写入日志或工作区数据库。 |
| `OPENAI_ADMIN_API_KEY` | OpenAI 管理侧的后续额度/组织信息同步、连接测试 | 仅由服务器读取；不得提交、返回至浏览器、写入日志或工作区数据库。 |

在凭据进入项目配置后，应先执行**只读连接测试**，记录成功/失败时间、provider 状态与错误类别。连接测试失败、限流或返回未知字段时，Provider Adapter 必须保持禁用，不得回退到任何浏览器登录态或 ChatGPT Plus 个人会话。

## 2. Provider 最小权限与上线核查

启用真实同步前，应以供应商当期官方文档为准，确认令牌只包含所需的只读额度、组织、用量或模型目录权限。不得使用具有账单修改、成员管理、密钥管理、项目删除或其他写权限的凭据，除非后续需求明确、经过 owner 复核并新增审计记录。

| 核查项 | 上线要求 |
| --- | --- |
| API 范围 | 使用最低可行的只读范围；记录供应商文档链接和验证日期。 |
| 网络与超时 | 设置显式连接/读取超时；遵守 Provider 限流；错误按 QUOTA、RATE_LIMIT、TIMEOUT、PROVIDER_ERROR 等故障域归类。 |
| 同步节奏 | 使用平台管理的 Heartbeat 回调与数据库租约锁；不得部署常驻 worker 或进程内定时器。 |
| 执行开关 | 先启用额度同步，再由 owner 显式评估是否启用真实 Provider Adapter；两者不能因存在 API Key 而自动联动。 |
| 研究完整性 | `official`、`fallback`、`exploratory`、`recovery` 结果保持分层；正式实验不接受 provisional 结果。 |

## 3. 数据保留与删除策略

QuotaPilot 当前将任务、attempt、预算预留、额度快照、用量导入元数据、路由决策、队列事件、治理审计与实验账本作为可审计控制面记录。默认策略为**不自动清理审计元数据**，直至工作区 owner 确认研究机构、课题组或项目的数据保留要求。Provider 密钥不进入应用数据库；导入文件内容不进入公开仓库。

建议在首次真实同步前由 owner 明确以下工作区策略，并在后续管理界面/数据迁移中实施：

1. 明确 usage 导入原文件、原始 Provider 响应是否需要留存；若无需留存，只保留规范化元数据和校验和。
2. 为不可变实验账本、任务事件和治理审计分别定义保留期限与合法删除审批人；删除应产生日志而非静默移除。
3. 定义已取消任务、过期预留和失效模型版本的归档窗口；历史版本及审计证据不可被后续活跃配置覆盖。
4. 在导出、备份和数据库访问层实施工作区隔离；公开 GitHub 仓库不得包含任何实际用量导入文件、用户数据、日志、凭据或数据库连接串。

## 4. 建议的上线顺序

1. Owner 审阅本说明、供应商最新 API 文档和最低权限要求。
2. 安全配置 Secrets，并通过服务器端只读连接测试。
3. 验证动态模型目录字段、上下文容量、额度窗口与 reset 时间的映射；未验证字段必须标记为未知而不是猜测。
4. 先启用小范围、只读的额度同步，观察路由审计、预算快照和告警。
5. 在隔离工作区执行 Provider Adapter 演练，确认并发、失败域、成本封顶、结果分层和数据保留策略。
6. 只有在 owner 再次确认后，才考虑启用真实任务调用；此步骤不属于当前离线版本。
